# Мастер публикаций Drafta — preview

## Запуск

1. Применить миграции `20260914120000_publication_authoring.sql` и
   `20260914130000_publication_publishing.sql` обычным процессом
   Supabase к окружению preview. Предыдущая миграция публикаций обязательна.
2. В серверном окружении preview задать `OPENAI_API_KEY`. Дополнительные настройки:
   `OPENAI_PUBLICATION_TEXT_MODEL` (по умолчанию `gpt-5.6-terra`) и
   `OPENAI_PUBLICATION_IMAGE_MODEL` (по умолчанию `gpt-image-2.5-flare`).
   Проверить доступ проекта OpenAI к моделям. Ключ не передаётся браузеру.
3. Синхронизировать Inngest: должны быть зарегистрированы `publication-generation`
   `recover-publication-generations`, `publication-send` и `recover-publication-deliveries`.
   Нужны штатные ключи Inngest, Supabase и `ZERNIO_API_KEY`.
4. Проверить описание OpenAI API в списке субпроцессоров и публичной privacy page;
   условия пользовательского ChatGPT не заменяют договорные настройки API.

Без ключа доступны выбор настроек и их сохранение; кнопки генерации отключены.
Ключи/миграции удалённого окружения кодом автоматически не устанавливаются.

## Ручная приёмка

- «Публикации → Создать»: рядом видны Drafta и ChatGPT.
- Первый шаг показывает только active-подключения текущего workspace; выбрать два
  канала и знания. Доступны все четыре формата: текст, картинка, карусель и сценарий видео.
- «Далее» не вызывает LLM, открывает шесть редактируемых полей.
- «Предложить идеи» выдаёт три идеи; три дополнительных запроса доводят число до 12.
  Обновление страницы/повторный вход не сбрасывает лимит. Выбор идеи заполняет поля.
- Смена языка/знаний/каналов помечает прошлые идеи как устаревшие, не стирая их.
- Текстовый маршрут пропускает картинку. После генерации доступны версии каналов.
- Маршрут с картинкой принимает описание, стиль, пропорции, необязательный референс
  или собственный файл. Загруженный готовый файл используется без изменения.
- Проверить реальную генерацию в трёх пропорциях. `medium`, PNG, одна картинка.
  Проверить читабельность надписи; личные идентификаторы в изображение не включаются.
- Закрыть окно во время генерации, вернуться: результат появляется для проверки.
- Сбой Image API после готового текста: повторить, убедиться, что usage текста
  не добавился вторично. Максимум три пользовательские попытки задачи.
- Изменить текст вручную, сохранить. Перегенерация предлагает новую версию,
  принятие — отдельное действие. Проверить конфликт редактирования в двух вкладках.
- Проверить старый OAuth/Custom GPT: нативные черновики ему не видны.

- Карусель: предложить и отредактировать структуру, создать слайды, поменять порядок,
  заменить один своим файлом, изменить другой через AI. Остальные слайды неизменны.
- «Изменить текст с AI»: указать пожелание; меняется выбранная версия соцсети.
  Отклонение сохраняет прежний материал. Для изображения edits использует оригинал.
- Сценарий: задать длительность и формат съёмки, проверить сцены/реплики/тайминг,
  изменить отдельную сцену по инструкции и скопировать результат. Отправки нет.
- Предпросмотр: текст в LinkedIn, текст + фото в Instagram, карусель в обе сети.
  LinkedIn получает PDF, Instagram — серию JPEG. Проверить реальные ссылки и порядок.
- Частичный сбой: успешная цель остаётся опубликованной, повторяется только неудачная.
  После сетевого таймаута проверить отсутствие дублей и восстановление по metadata.
- Проверить разрешения подключений: Instagram Business/Creator, LinkedIn выбранный
  личный профиль либо страница компании. При необходимости переподключить канал.
- Удалить обычный черновик и сценарий. Во время генерации/отправки удаление отклоняется.
  Удаление отправленного материала не должно удалять пост в соцсети.
- Проверить фильтры «Черновики», «Опубликованные», «Сценарии», «Ошибки отправки».

Реальные проверки отправки выполняются на согласованных тестовых подключениях:
они создают публичные посты. Автоматические тесты используют mocks и локальную БД.
Веб-поиск, календарь отправки, создание/публикация видеофайлов и биллинг пользователей
отложены. Существующие настройки OpenAI сохранены; новые API-ключи не нужны.

## Проверки

`npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`.

SQL-контракты можно прогнать без Docker в изолированном PostgreSQL WASM:

```powershell
npm install --prefix "$env:TEMP/drafta-publication-sql" --no-audit --no-fund @electric-sql/pglite
$env:PUBLICATION_SQL_RUNTIME = Join-Path $env:TEMP 'drafta-publication-sql'
node scripts/test-publication-authoring.mjs
```

Скрипт применяет реальные миграции публикаций к временной БД с минимальными
инфраструктурными таблицами. Проверяет RLS, FK, ревизии, идемпотентность, лимиты,
повторы и защиту ручных правок. Он не обращается к Supabase из `.env` и не заменяет
полную проверку миграций/RLS в локальном Supabase и preview.
