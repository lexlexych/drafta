# E-002. Zernio-контур: адаптер, вебхук, Realtime-инбокс «Сообщения»

## Цель

Работающий контур входящих DM: адаптер Zernio в `lib/channels/` парсит вебхуки в
нормализованные события, вебхук-роут идемпотентно раскладывает их в БД
(contact → conversation → message) и отвечает < 1 сек, в настройках подключаются
каналы (несколько аккаунтов одной платформы, пользовательские имена), а
Realtime-инбокс «Сообщения» показывает диалоги с именем канала-источника —
реальное сообщение в Telegram появляется в инбоксе за секунды.

## В скоупе

- Ядро слоя каналов: нормализованные типы событий, интерфейс адаптера, реестр
  провайдеров, дефолтные capabilities платформ — `lib/channels/`
- Адаптер Zernio (только DM): проверка подписи, парсинг payload → нормализованные
  события, юнит-тесты на фикстурах
- Вебхук-роут `app/api/webhooks/[provider]` с идемпотентностью через `webhook_events`:
  upsert contact_identity (+contact), conversation, insert message, эмиссия
  `interaction/received` (только ID), ответ 200 < 1 сек
- Настройки → Каналы: список подключений, добавление Zernio-канала, несколько
  аккаунтов одной платформы, пользовательские имена, переименование, отключение
- Инбокс «Сообщения»: список диалогов `kind = dm` со всех каналов с бейджем
  имени канала-источника, тред, счётчики непрочитанного, фильтр по каналу
- Realtime: новое входящее появляется в открытом инбоксе без перезагрузки
- Ручные шаги (executive summary): подписанный DPA Zernio, аккаунт и API-ключ Zernio,
  вебхук-URL и секрет, env-переменные, подключение реального Telegram, туннель для
  локальной отладки, сверка живых payload'ов с фикстурами

## Вне скоупа

- AI-черновики, Inngest-функция `generate-draft`, дебаунс, маскирование — этап 2;
  в этом эпике только эмиссия события `interaction/received` из вебхука (без обработчиков)
- Исходящие (`send-message`, статусы доставки, 24-часовое окно) — этап 3;
  операция «отправить» в адаптере остаётся нереализованной заглушкой
- Комментарии: comment-вебхуки, `kind = comments`, группировка по постам — этап 5;
  тип `comment.received` объявляется в нормализованных типах, но не обрабатывается
- Раздел контактов, карточка, склейка — этап 7; контакты создаются автоматически в БД
- Push-уведомления, PWA — этап 9; только Realtime в открытой вкладке
- Панель черновика в треде — этап 2; mock-заглушка панели из E-001/T-07 остаётся, но не подключается
- Email-адаптер (Postmark) и прямая интеграция Meta — этапы 11+
- Загрузка/превью файлов-вложений: сохраняются метаданные, в UI — индикатор
  «вложение» (открытый вопрос №4)

## Критерий готовности эпика

Критерий этапа 1: **реальное сообщение в Telegram появляется в инбоксе за секунды** —
с именем канала-источника у диалога и без перезагрузки страницы (Realtime).
Дополнительно: повторная доставка того же вебхука (ретрай Zernio) не создаёт
дублей сообщений; два подключения одной платформы различимы в инбоксе по именам.

## Открытые вопросы

1. **Доступ к документации/сэндбоксу Zernio API.** В архитектуре не зафиксированы
   точный формат вебхук-payload, механизм подписи и способ привязки аккаунтов
   соцсетей (ссылка из API или только дашборд Zernio). Тикеты T-02/T-04 исходят из
   допущений: HMAC-подпись по секрету, привязка аккаунта на стороне Zernio + ручной
   ввод внешнего ID. Нужны доки/доступ; после первых живых вебхуков фикстуры
   сверяются с реальностью (шаг T-07) — это «самый рискованный этап» по §17.
2. **Эмиссия Inngest-события на этапе 1.** Пайплайн §7.1 заканчивается
   `inngest.send("interaction/received")`, но настройка Inngest — этап 2. Решение
   в T-03: событие эмитится fail-safe (ошибка эмиссии логируется и не ломает
   обработку вебхука; обработчиков события до этапа 2 нет). Подтвердить, либо
   перенести эмиссию целиком в этап 2.
3. **Статус DPA Zernio.** Подписанный DPA — входное условие этапа 1 (запрошен в
   E-001/T-08, шаг 8). Dev-тикеты T-01–T-06 выполняются на фикстурах и без DPA,
   но живое подключение (T-07) — только после подписания.
4. **Вложения.** На этапе 1 сохраняются только метаданные вложений (в `messages`),
   в UI показывается индикатор «вложение» без загрузки и превью файлов.
   Подтвердить, что этого достаточно до отдельной проработки.
