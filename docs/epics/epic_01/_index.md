# E-001. Фундамент: Next.js + Supabase Auth, схема БД v1, RLS

## Цель

Рабочий фундамент продукта: Next.js-приложение со структурой каталогов из архитектуры,
Supabase Auth (регистрация/вход/сброс пароля), полная схема БД v1 миграциями — все
таблицы §6 с `workspace_id`, RLS-политиками и каскадным удалением, — сиды локальной
разработки и автотесты изоляции тенантов. Поверх фундамента — полный UI-каркас
приложения по макету `docs/references/ui-mockup.html` на mock-данных: последующие
эпики дорабатывают этот UI и замещают mock-данные реальными интеграциями.
Ручными шагами настраиваются прод-окружения
(Supabase Frankfurt, Vercel fra1) и Postmark как custom SMTP; параллельно запрашивается
DPA у Zernio.

## В скоупе

- Каркас Next.js (App Router, TypeScript) со структурой каталогов по §12, линтом, сборкой и тест-раннером
- Инициализация Supabase (локальная разработка) и схема БД v1 **миграциями**: все 15 таблиц §6,
  включая пока пустые `kb_files` и `invitations`; каскады от workspace; уникальности
- RLS: политики изоляции «участник видит только свои workspace'ы» на всех таблицах
- Supabase Auth в приложении: регистрация, вход, выход, сброс пароля; клиенты Supabase в `lib/db`
- Создание workspace при онбординге нового пользователя (роль owner) + защищённая зона приложения
- Сиды локальной разработки и автотесты RLS-изоляции
- UI-каркас всех разделов по макету `docs/references/ui-mockup.html` на mock-данных:
  дашборд, сообщения, комментарии, контакты, настройки; десктопная и мобильная
  компоновки; mock-данные изолированы в одном модуле под замену реальными
- Ручные шаги (executive summary): проекты Supabase prod/dev во Frankfurt, Vercel fra1,
  домен + DKIM в Postmark, custom SMTP в Supabase Auth, лимиты auth-писем, запрос DPA у Zernio

- Системная категория «по умолчанию» при создании workspace — этап 6; таблица `categories` создаётся пустой

- PWA, Serwist, Web Push — этап 9

## Критерий готовности эпика

Регистрация с реальным email проходит (письмо подтверждения приходит через Postmark),
и два зарегистрированных пользователя не видят данные друг друга — у каждого свой
workspace, изоляция подтверждена и автотестами RLS, и ручной проверкой в проде.

## Открытые вопросы

1. **Домен для писем Postmark** — в документации не зафиксировано, какой домен
   использовать для отправки auth-писем (и позже email-канала). Нужен домен во владении
   человека; выбор/покупка — ручной шаг T-08.
2. **Тест-раннер не зафиксирован в архитектуре.** В тикетах предложен Vitest
   (де-факто стандарт для Next.js + TypeScript). Если есть предпочтение (Jest, node:test) —
   сказать до старта эпика.
3. **Docker для локального Supabase.** `supabase start` требует Docker Desktop на машине
   разработки (Windows). Если Docker недоступен, тикеты T-02–T-06 потребуют dev-проекта
   Supabase в облаке вместо локального стека — это изменит DoD тикетов.
4. **Пакетный менеджер** — в тикетах предполагается npm. Если предпочтителен pnpm/yarn —
   сказать до старта эпика.
