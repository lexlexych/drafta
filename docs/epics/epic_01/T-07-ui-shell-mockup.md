# T-07. UI-каркас приложения по макету ui-mockup.html на mock-данных

## Цель

В защищённой зоне работает полный UI-каркас приложения, перенесённый из макета
`docs/references/ui-mockup.html` в Next.js-компоненты: разделы Дашборд, Сообщения,
Комментарии, Контакты, Настройки с десктопной (левое меню + список + тред + панель
черновика) и мобильной (< 900px, нижний таббар, панельная навигация) компоновками.
Все данные — mock, изолированные в одном модуле. **Последующие эпики дорабатывают
этот UI и замещают mock-данные реальными интеграциями** — компоненты проектируются
под такую замену.

## Контекст

Обязательно прочитать перед выполнением:

- `docs/references/ui-mockup.html` — **источник вёрстки и поведения**: один
  самодостаточный HTML (vanilla JS + mock-данные), открывается в браузере без сборки
- [10. UI и навигация](../../architecture/10-ui.md) — вся глава: левое меню, нижняя
  панель, «откуда пришло входящее», экраны инбокса, разделы настроек
- [2. Глоссарий](../../architecture/02-glossary.md) — термины обязательны в именах
  компонентов, типов и mock-данных (workspace, channel_connection, conversation…)
- [12. Структура репозитория](../../architecture/12-repo-structure.md) — маршруты
  `app/(app)/`: `dashboard`, `inbox`, `comments`, `contacts`, `settings`
- [6. Модель данных](../../architecture/06-data-model.md) — форма mock-типов должна
  повторять таблицы §6, чтобы замена на реальные данные не требовала переписывания UI

Существенные факты:

- T-05 создал защищённую зону `app/(app)/` и минимальную страницу `dashboard` —
  этот тикет заменяет её дашбордом из макета и добавляет остальные разделы.
- Сигнатурный элемент макета — панель AI-черновика на янтарной «бумажной» подложке
  с действиями принять / править / отклонить / заново; в этом тикете все действия —
  заглушки (LLM — этап 2, отправка — этап 3).
- В макете есть: расхлоп «Сообщения»/«Комментарии» по каналам, фильтр по категории
  в шапке списка, расхлоп «Контакты» с фильтром по каналу; на десктопе список
  разделов настроек скрыт (дублирует расхлопнутое меню), виден только на мобайле.
- Дашборд в макете иллюстративный — переносится как есть, с пометкой в коде.
- Раздел «База знаний» в макете отсутствует — не добавлять (этап 4).
- Никакой логики каналов/провайдеров здесь нет: mock-данные — это просто данные,
  правило 4 (`lib/channels/`) не задействуется.

## Шаги реализации

1. Изучить макет в браузере и его исходник; зафиксировать список экранов,
   состояний и переходов (десктоп и мобайл).
2. Mock-данные вынести в отдельный модуль (например, `lib/mock/`): типизированные
   по глоссарию и §6 наборы — каналы, контакты, диалоги, сообщения, комментарии
   к постам, категории, черновики. Контент можно взять из макета (Tonwerk Keramik).
   **Компоненты получают данные только через пропсы/загрузчики — вшитых данных
   внутри компонентов нет.**
3. Общий layout защищённой зоны: десктопное левое меню (лого, пункты со счётчиками,
   расхлопы по каналам) и мобильный нижний таббар с тем же набором разделов.
4. Разделы-маршруты по §12: `dashboard` (иллюстративный), `inbox` (список диалогов +
   тред + панель черновика), `comments` (посты и ветки комментариев + панель
   черновика), `contacts` (список с фильтром по каналу + карточка), `settings`
   (разделы из макета: каналы, категории, AI и т.д. — формы-заглушки).
5. Перенести стили и интерактив макета в компоненты: переключение разделов —
   маршрутами, фильтры по каналу/категории, тред, действия панели черновика —
   заглушки без побочных эффектов. Пиксель-перфект не требуется, структура,
   иерархия и сигнатурная панель черновика — обязательны.
6. Мобильная компоновка < 900px: нижний таббар, список → тред → назад.
7. Смоук-тесты на рендер разделов (страницы открываются, ключевые элементы на месте).

## Критерии приёмки

- [ ] Все пять разделов открываются в защищённой зоне и соответствуют макету по структуре
- [ ] Десктоп: левое меню с расхлопами и счётчиками; мобайл (< 900px): нижний таббар, панельная навигация
- [ ] Панель AI-черновика присутствует в треде сообщений и в комментариях; действия — заглушки
- [ ] Все mock-данные живут в одном модуле; в компонентах вшитых данных нет
- [ ] Имена типов/компонентов следуют глоссарию (workspace, а не account; channel_connection и т.д.)
- [ ] Форма mock-типов согласована с таблицами §6 (id, workspace_id, поля по модели данных)
- [ ] Неавторизованный доступ к разделам по-прежнему редиректит на вход (гейт T-05 не сломан)
