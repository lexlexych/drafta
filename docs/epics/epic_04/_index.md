# E-004. Миграция основного приложения с Inngest на Vercel Workflow

## Цель

Перенести 13 существующих фоновых функций основного приложения на Vercel Workflow и удалить неиспользуемую generate-comment-drafts. Ошибки пользовательских операций видны в UI и повторяются вручную; только push и две очистки допускают до двух автоматических повторов.

## Критерий готовности эпика

Все 13 workflow запускаются из реальных действий/вебхуков/Cron. Входящее появляется в инбоксе; ручная генерация даёт черновик; ошибка отправки видна, ручной повтор отправляет ровно одну логическую операцию. Автоответ при ошибке повторяется кнопкой в треде, Stop/ответ оператора не допускают поздней отправки. Публикация/импорт продолжают только незавершённые этапы; проверка uncertain ничего не отправляет. Push и очистки ограничены двумя дополнительными попытками. SQL/RLS и конкурентные тесты проверяют изоляцию, fencing и двойной запуск, smoke проходит после каждой фичи. Основной продукт не использует Inngest; облачный регион/дренирование/ручной acceptance подтверждены T-08.

## Открытые вопросы

Нет: продуктовые решения приняты пользователем. Совместимость закреплённого SDK, фактические облачные настройки и доступность локального SQL target проверяются при реализации; облачные действия и точные инструкции заносятся в T-08, без повторного согласования уже принятой политики.

Ключевые риски: неизвестный результат внешней отправки, завершение старого attempt после нового, длительные шаги генерации, утечка контента через сериализацию, незавершённые старые Inngest run при переключении. Каждый покрыт критериями соответствующих тикетов.
