# T-02. Операции и попытки: атомарный запуск, блокировки, отмена и восстановление

## Цель

Каждая операция имеет одну активную попытку, безопасно запускается и восстанавливается после сбоев; устаревший run не может изменить новое состояние.

## Контекст

[План, §4, §6–7](../../plans/inngest-to-vercel-workflow.md), [мультитенантность](../../architecture/04-multitenancy.md), [модель данных](../../architecture/06-data-model.md), [потоки](../../architecture/07-data-flows.md), [UI](../../architecture/10-ui.md), [GDPR](../../architecture/15-compliance-gdpr.md), T-01. Подробные результаты остаются в существующих предметных таблицах.

Общие обязательные источники: [глоссарий](../../architecture/02-glossary.md), [правила](../../architecture/14-vibecoding-rules.md). Прямое решение пользователя заменяет требования Inngest и автоматических retry: основное приложение переходит на Vercel Workflow; архитектуру синхронизирует T-07. `website/` исключён из изменений.

## Шаги реализации

1. Создать миграциями workflow_operations и минимально необходимые записи попыток/блокировок: workspace_id, RLS, каскад; operationId, attemptId, runId, kind, subject ID, engine, status, timestamps, безопасный error code. Детальный контент не переносить в историю Workflow. Не менять все предметные enum ради универсального состояния.
2. Реализовать атомарные RPC регистрации/claim/retry/cancel/finalize с проверкой workspace и актуального attemptId. Стабильный бизнес-ключ операции отделить от новой попытки и run. Двойной клик/дубли start возвращают существующую активную попытку.
3. Добавить ограниченные leases с owner/fencing token и правилами освобождения/продления: последовательность по conversation/post/delivery и существующие workspace limits. Слоты разных workflow согласовать; спящий автоответ не занимает workspace/conversation slot. Истёкший lease сам по себе не разрешает повтор внешней отправки.
4. Добавить серверные start/status/retry/cancel и общий формат UI состояний failed/uncertain/cancelled. Проверять membership и принадлежность объекта до privileged DB access. Отмена инвалидирует attempt в БД до вызова API SDK.
5. Покрыть accepted/failed/unknown start; предусмотреть durable intent для webhook-инициированных операций, без неуправляемого fire-and-forget и без потери входящего. Run с неизвестным результатом старта не получает право на вторую внешнюю отправку.
6. Добавить сверку зависших состояний по run status и lease при загрузке UI; работающий run не перезапускается по одному возрасту. Для фонового обслуживания подготовить reusable reconciliation. Технический повтор фиксации БД допускается, но не включает повтор LLM/send.

## Критерии приёмки

Ниже — итоговый acceptance, включая живое окружение; локальная реализация завершена, подтверждение полного сценария отмечается при T-08.

- [ ] Тесты атомарности показывают: два start/retry создают одну активную попытку; новый attempt не наследует право старого run на финализацию.
- [ ] Отмена и финализация старого attempt не меняют новый attempt и его предметный результат. Истёкший владелец блокировки не может отправлять/записывать результат.
- [ ] Сохраняются исходные лимиты: пользовательские workspace 2 и одна операция conversation/post; push workspace 4; по contact identity/post/job/import/delivery один владелец. Указать в отчёте точные ключи и cross-workflow semantics.
- [ ] Чужой workspace не может читать/запускать/повторять/отменять операцию; составные принадлежности проверены RPC и сервером; служебные функции недоступны anonymous напрямую.
- [ ] Сбой start/аварийный run/сбой фиксации failed не оставляет UI навсегда busy: статус сверяется и доступно безопасное действие; живой run повторно не стартует.
- [ ] Unknown send — отдельное состояние; сервер не разрешает обычный retry без сверки либо явного подтверждения проверки в канале. Стабильный idempotency key сохраняется.
- [ ] Есть тесты реальной SQL/RLS/конкурентности, а не только мок результата RPC; для global cleanup не создаются tenant-данные без workspace.

## Definition of Done

`pnpm exec vitest run <tests операций и действий>`, исполняемые SQL/конкурентные тесты на изолированной локальной PostgreSQL (или совместимом PGlite), `pnpm exec tsc --noEmit`, `pnpm lint`. Тестовая RLS allowlist `lib/rls-test-targets.ts` сейчас пуста: не добавлять production/неизвестный Supabase target. `pnpm test:rls` и `pnpm exec supabase test db` запускать только на разрешённом локальном тестовом target; при отсутствии зафиксировать точную причину и воспроизводимые команды в T-08, не объявлять эти проверки пройденными. Smoke: новая операция → ошибка start → ручной retry → отмена → устаревшая финализация; `pnpm exec vitest run 'app/(app)/(shell)/smoke.test.tsx' --maxWorkers=1 --no-file-parallelism`.
