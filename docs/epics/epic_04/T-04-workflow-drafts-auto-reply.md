# T-04. AI-черновик и автоответ: отмена, пауза и ручной повтор в переписке

## Цель

Черновик и автоответ работают через Workflow, отменяются без поздней перезаписи, ошибки автоответа повторяются только вручную в переписке.

## Контекст

[План, §4–5](../../plans/inngest-to-vercel-workflow.md), [потоки, генерация и автоответ](../../architecture/07-data-flows.md), [AI](../../architecture/08-ai-subsystem.md), [модель](../../architecture/06-data-model.md), [UI](../../architecture/10-ui.md), T-02/T-03. Пользователь подтвердил 0 retry автоответа и удаление неиспользуемой generate-comment-drafts. Текущее поведение ручной генерации DM важнее исторического E-003 с debounce на входящее.

Общие обязательные источники: [глоссарий](../../architecture/02-glossary.md), [правила](../../architecture/14-vibecoding-rules.md). Прямое решение пользователя заменяет требования Inngest и автоматических retry: основное приложение переходит на Vercel Workflow; архитектуру синхронизирует T-07. `website/` исключён из изменений.

## Шаги реализации

1. Создать generateDraftWorkflow с текущей ручной генерацией, маскированием, использованием базы знаний и supersede. Ошибка снимает generating; повтор по существующему действию. Не включать автоматическую генерацию на входящее.
2. Кнопка Stop отменяет attempt в БД и run в SDK; финализация проверяет fencing/attemptId. Контекст, промпт и ответ LLM остаются внутри шага/БД, не в serialized outputs. Сохранить вызовы моделей только lib/ai и maxRetries = 0.
3. Создать autoReplyWorkflow: durable sleep от последнего входящего → повторная проверка актуальности → выбор сценария/шаблона → идемпотентная регистрация sendMessageWorkflow. Не удерживать бизнес-lock во время sleep.
4. Новое входящее, ручной ответ оператора, отключение настройки и cancel инвалидируют старый автоответ; перед ручным retry заново проверить последнее входящее, окно ответа, сценарий и отсутствие уже отправленного ответа.
5. До создания сообщения показать в переписке ошибку «Автоответ не выполнен» и действие «Повторить автоответ»; после создания использовать UI сообщения. Ошибка регистрации дочернего run не оставляет pending навсегда. Журнал отличает queued от подтверждённой отправки.
6. Удалить generate-comment-drafts, регистрацию, event/emitter, отдельный pipeline и только относящиеся к ней мёртвые tests. Общие AI/DB helpers сохранять по ссылкам; исторические таблицы/данные не удалять.

## Критерии приёмки

Ниже — итоговый acceptance, включая живое окружение; локальная реализация завершена, подтверждение полного сценария отмечается при T-08.

- [ ] Черновик выполняет один вызов LLM при ошибке; поле ответа разблокируется; повтор инициирует пользователь. Stop и новый attempt защищены от позднего результата.
- [ ] AutoReplyWorkflow не повторяет ни модель, ни отправку автоматически. Ошибка до сообщения видна в реальном треде с рабочим retry action.
- [ ] Durable sleep сохраняет существующую паузу и не расходует lock slot; новый входящий/ответ оператора делает старый run неактуальным.
- [ ] Двойной manual retry и повтор старого run не создают второе исходящее; sendMessageWorkflow использует один business key; queued не записывается как sent.
- [ ] generate-comment-drafts не существует в рабочем контуре; ручные комментарии, шаблоны, переводы и существующие данные сохранены.
- [ ] Тесты проверяют отмену во время внешнего вызова, fencing результата, автоответ после ответа оператора и failure дочернего start.

## Definition of Done

`pnpm exec vitest run <draft/auto-reply pipelines, actions и UI tests>`, тесты masking через `pnpm exec vitest run lib/ai`, `pnpm exec tsc --noEmit`, `pnpm lint`; smoke ручного черновика/Stop и auto-reply fail → retry в треде. Обязательный smoke после фичи: `pnpm exec vitest run 'app/(app)/(shell)/smoke.test.tsx' --maxWorkers=1 --no-file-parallelism`.

## 🔧 Отчёт разработчика

Черновик и автоответ переведены на Workflow без бизнес-retry. Пауза автоответа использует durable sleep до захвата слота. Отмена и проверки актуальности сохранены; ручной повтор использует созданное исходящее. Журнал фиксирует queued до подтверждённой доставки. Неиспользуемая generate-comment-drafts и её пайплайн удалены, исторические данные сохранены.

Проверки и ограничения общего интеграционного прогона записаны в [T-08](T-08-executive-summary.md#результаты-локальных-проверок-2026-09-21). Непроверенные живые сценарии остаются критериями ручного acceptance.
