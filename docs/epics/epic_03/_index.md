# E-003. AI-черновики с дебаунсом: Inngest + Mistral, generate-draft, панель черновика

## Цель

Работающий контур AI-черновиков для DM: событие `interaction/received` из вебхука
(эмитится с E-002) обрабатывает Inngest-функция `generate-draft` с нативным дебаунсом
по диалогу и периодом из `ai_settings`; перед вызовом LLM идентификаторы (телефоны,
email, IBAN, карты) маскируются плейсхолдерами с обратной подстановкой; при генерации
нового черновика прежний `ready`-черновик помечается `superseded`. Панель черновика
из UI-каркаса (E-001/T-07) подключается к реальным `drafts`: показ, правка, отклонение,
регенерация — черновик появляется в открытом треде без перезагрузки.

## В скоупе

- Inngest-контур: `app/api/inngest/route.ts` (serve), типизированные схемы событий
  (`interaction/received`, `draft/regenerate.requested` — payload строго только ID),
  локальная разработка через Inngest Dev Server
- Клиент LLM в `lib/ai`: OpenAI-совместимый SDK, Mistral по умолчанию, OpenRouter —
  fallback по env-переменным; вызовы LLM только через `lib/ai` (правило 9)
- Маскирование `lib/ai/masking.ts` (телефоны, email, IBAN, карты → `{{PHONE_1}}` и т.п.)
  с обратной подстановкой и обязательными юнит-тестами
- Сборка промпта по структуре §8 (тон/язык из `ai_settings`, замаскированный контекст,
  правила канала из capabilities, защита от инъекций); слоты под базу знаний (этап 4)
  и действие категории (этап 6) заложены, но пусты; debug-лог замаскированного
  промпта за env-флагом
- Inngest-функция `generate-draft`: дебаунс по `conversationId` с периодом из
  `ai_settings.debounce_seconds`, стоп-чек авто-генерации, пайплайн шагами,
  supersede-логика, конкурентность `limit: 2` per workspace; регенерация по
  событию без дебаунса
- Настройки → AI: форма реальных `ai_settings` (тон, язык, подпись, дебаунс,
  авто-генерация, модель) вместо mock-заглушки
- Панель черновика в треде «Сообщения»: реальные `drafts` со статусами
  (`generating`/`ready`/`edited`), Realtime-появление без перезагрузки, действия
  править / отклонить / сгенерировать заново; «принять» — заглушка до этапа 3
- Ручные шаги (executive summary): Inngest Cloud + интеграция с Vercel + DPA,
  аккаунт Mistral + `MISTRAL_API_KEY` + DPA/no-training, env-переменные,
  финальная проверка критерия этапа

## Критерий готовности эпика

Критерий этапа 2: **три сообщения подряд в один диалог → ровно один черновик после
паузы дебаунса**, и он появляется в панели открытого треда без перезагрузки;
**телефон в сообщении не уходит в LLM** — в debug-логе промпта виден плейсхолдер
(`{{PHONE_1}}`), а в готовом черновике при необходимости телефон подставлен обратно.
Дополнительно: повторная генерация помечает прежний `ready`-черновик `superseded`
(пользователь никогда не видит два конкурирующих черновика); при выключенной
авто-генерации черновик не создаётся.

## Открытые вопросы

1. **Динамический период дебаунса.** Архитектура (§7.2) требует период из
   `ai_settings.debounce_seconds` per-workspace, но конфиг нативного debounce Inngest
   может допускать только статический период. Решение в T-05: если динамический период
   в конфиге невозможен — паттерн «`step.sleep(debounce_seconds)` → проверка, что
   событие всё ещё последнее в диалоге» с фиксацией отклонения в отчёте. Подтвердить.
2. **Модель Mistral по умолчанию** не зафиксирована в архитектуре (env описывает
   только `OPENROUTER_MODEL`). Тикеты предлагают конфигурируемый дефолт в `lib/ai`
   (предложение — `mistral-small-latest` как баланс цены/качества для черновиков)
   с переопределением через `ai_settings.model`. Утвердить модель до живых вызовов.
3. **«Принять» на этапе 2** остаётся заглушкой с пометкой «отправка — этап 3»
   (отправка ответа — скоуп этапа 3). Подтвердить, что это ожидаемое поведение.
4. **Судьба `edited`-черновика при новой генерации.** §7.2 предписывает supersede
   только для статуса `ready`. Тикеты следуют букве архитектуры: `edited` черновик
   не супersede'ится автоматически (правки пользователя не выбрасываются молча).
   Подтвердить или уточнить желаемое поведение.
5. **Debug-лог промпта.** Критерий этапа требует видеть плейсхолдер «в логе промпта»,
   но §15.2 предостерегает от контента в логах Vercel. Решение: лог замаскированного
   промпта только при env-флаге `AI_LOG_PROMPTS=true`, по умолчанию выключен
   (проверка критерия — локально/dev). Подтвердить.
6. **DPA Mistral и Inngest** — входные условия для прогона живых данных через контур
   (аналог DPA Zernio на этапе 1): dev-тикеты работают на тестах с мок-LLM, живые
   вызовы — после шагов T-08. Подтвердить, что подписание берёт на себя человек
   параллельно с разработкой.
