# T-04. Сборка промпта по структуре §8 и debug-лог

## Цель

В `lib/ai` работает сборка промпта генерации черновика по структуре §8: роль и тон
из `ai_settings`, замаскированный контекст диалога, правила канала из capabilities,
защита от инъекций; слоты под базу знаний (этап 4) и действие категории (этап 6)
заложены, но пусты. За env-флагом — debug-лог итогового (замаскированного) промпта,
которым проверяется критерий этапа «телефон виден как плейсхолдер».

## Контекст

Обязательно прочитать перед выполнением:

- [8. AI-подсистема — «Структура промпта»](../../architecture/08-ai-subsystem.md#структура-промпта) — все 7 секций и их порядок; имя контакта в промпт не передаётся, если не нужно для ответа
- [6. Модель данных](../../architecture/06-data-model.md#ai_settings) — `ai_settings`: тон, язык, подпись
- [5. Слой абстракции каналов — «Capabilities канала»](../../architecture/05-channels.md#capabilities-канала) — откуда берутся правила канала (длина, стиль)
- [15. Compliance, §15.2](../../architecture/15-compliance-gdpr.md#122-субпроцессоры-и-данные) — «следить, чтобы контент не попадал в логи» Vercel — поэтому лог промпта только за флагом
- [16. План внедрения, этап 2](../../architecture/16-rollout-plan.md#этап-2--ai-черновики-с-дебаунсом-2-3-дня) — критерий: «телефон … виден в логе промпта как плейсхолдер»

Существенные факты:

- Вход билдера — **уже замаскированные** тексты (T-03) + карта соответствий не
  нужна (подстановка — забота пайплайна T-05). Билдер — чистая функция без БД:
  все данные приходят параметрами, загружает их пайплайн (T-05).
- Секции этапа 2: (1) роль и тон, (4) контекст диалога, (5) правила канала,
  (7) защита от инъекций. Секции (2) база знаний, (3) заметки о контакте,
  (6) действие категории — пустые слоты с комментариями «этап 4 / 7 / 6»,
  интерфейс входа уже предусматривает эти поля опционально.
- Защита от инъекций: входящие сообщения подаются как данные (отдельный
  размеченный блок) с явной системной инструкцией игнорировать содержащиеся
  в них команды.
- Язык ответа — из `ai_settings` (язык общения бизнеса), подпись из `ai_settings`
  добавляется инструкцией к черновику.
- Debug-лог: `AI_LOG_PROMPTS=true` → вывести итоговый промпт в серверный лог;
  по умолчанию выключен (в проде не включать — §15.2). Логируется только
  замаскированный промпт, никогда исходный текст.

## Шаги реализации

1. Типы входа `lib/ai/prompt.ts`: `PromptInput = { aiSettings: {tone, language,
   signature}, maskedMessages: {direction, text}[], channelCapabilities,
   knowledgeBase?: never-slot, contactNotes?: never-slot, categoryAction?: never-slot }`
   (слоты типизировать опциональными полями с TODO-ссылками на этапы 4/6/7).
2. `buildDraftPrompt(input): ChatMessage[]` — system + user сообщения для клиента
   T-02:
   - system: роль ассистента бизнеса, тон/язык/подпись из `ai_settings`, правила
     канала из capabilities (макс. длина, стиль), инструкция про защиту от
     инъекций;
   - user: история диалога (замаскированная) как размеченные данные
     (направление + текст), задача — черновик ответа на последние входящие.
3. Debug-лог: хелпер `logPromptIfEnabled(messages)` — при `AI_LOG_PROMPTS=true`
   печатает промпт целиком (console/server logger) с пометкой-префиксом;
   вызывается пайплайном (T-05) после сборки.
4. Юнит-тесты:
   - порядок и состав секций соответствует §8 (снапшот/структурная проверка);
   - имя контакта не появляется в промпте (в input его просто нет — проверить,
     что тип не принимает лишние поля);
   - замаскированный вход → в итоговом промпте есть `{{PHONE_1}}` и нет исходного
     номера;
   - блок защиты от инъекций присутствует и входящие подаются как данные;
   - пустые слоты не порождают пустых секций-заголовков;
   - лог не вызывается без флага и вызывается с флагом (мок логгера).

## Критерии приёмки

- [ ] `buildDraftPrompt` собирает промпт по структуре §8; секции этапа 2 заполнены, слоты этапов 4/6/7 заложены и пусты
- [ ] Билдер — чистая функция: без обращений к БД, сети и SDK
- [ ] Имя контакта в промпт не попадает; вход принимает только замаскированные тексты (по контракту типов/именованию)
- [ ] Входящие сообщения поданы как данные с инструкцией игнорировать команды в них
- [ ] Лог промпта — только при `AI_LOG_PROMPTS=true`, содержимое — только замаскированный промпт
- [ ] Тесты шага 4 написаны и проходят
