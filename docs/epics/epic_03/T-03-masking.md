# T-03. Маскирование идентификаторов lib/ai/masking.ts + юнит-тесты

## Цель

Модуль `lib/ai/masking.ts` заменяет в тексте очевидные идентификаторы — телефоны,
email, IBAN, номера банковских карт — плейсхолдерами вида `{{PHONE_1}}` и умеет
выполнять обратную подстановку в готовый черновик. Модуль покрыт юнит-тестами
(обязательное требование правил вайбкодинга — «несущая стена»).

Существенные факты:

- Рынок запуска — Германия/ЕС: телефоны в первую очередь в форматах `+49…`, `0…`
  (и международные), IBAN в первую очередь `DE` (но формат IBAN общий — 2 буквы +
  2 цифры + до 30 знаков).
- Это regex-слой снижения рисков, не NER: полнота не требуется, ложные срабатывания
  вреднее пропусков — цены («49,90 €»), даты, номера заказов маскироваться не должны.
- Маскирование чистое (текст → текст + карта соответствий), без обращений к БД
  и SDK — модуль тривиально тестируется.
- Потребители: T-04 (сборка промпта) и T-05 (пайплайн — обратная подстановка).

## Шаги реализации

1. Типы: `MaskedResult = { maskedText: string; entities: MaskedEntity[] }`, где
   `MaskedEntity = { placeholder: string; kind: "phone" | "email" | "iban" | "card"; value: string }`.
2. `maskText(text: string, existing?: MaskedEntity[]): MaskedResult`:
   - детекторы: email; телефон (международный `+CC…` и немецкий национальный формат,
     с пробелами/скобками/дефисами, минимальная длина — чтобы не ловить цены и
     короткие числа); IBAN (валидация структуры, без обязательной проверки
     контрольной суммы); номер карты (13–19 цифр с пробелами/дефисами; проверка
     Луна для отсечения ложных срабатываний);
   - порядок применения: IBAN и карты до телефонов (пересечение цифровых
     последовательностей);
   - нумерация плейсхолдеров сквозная по типу: `{{PHONE_1}}`, `{{PHONE_2}}`,
     `{{EMAIL_1}}`…; одинаковое значение в разных местах/сообщениях получает один
     и тот же плейсхолдер; параметр `existing` позволяет маскировать несколько
     сообщений пачки с общей картой соответствий.
3. `maskMessages(texts: string[]): { masked: string[]; entities: MaskedEntity[] }` —
   обёртка для пачки сообщений диалога (общая нумерация).
4. `unmaskText(text: string, entities: MaskedEntity[]): string` — обратная
   подстановка в готовый черновик; плейсхолдеры, которых нет в карте, остаются
   как есть (не падать).
5. Юнит-тесты (обязательные):
   - немецкий и международный телефон в разных написаниях → `{{PHONE_N}}`;
   - email, IBAN (`DE…` и другой страны), номер карты (с пробелами, проходящий Луна) → маскируются;
   - цена «49,90 €», дата «12.03.2026», пятизначный номер заказа → **не** маскируются;
   - один и тот же телефон в двух сообщениях → один плейсхолдер;
   - несколько разных телефонов → `{{PHONE_1}}`, `{{PHONE_2}}`;
   - round-trip: `unmaskText(maskText(x)) `— исходные значения восстановлены;
   - `unmaskText` с неизвестным плейсхолдером не падает;
   - пустая строка / текст без идентификаторов → без изменений.

## Критерии приёмки

- [ ] `lib/ai/masking.ts` экспортирует mask/unmask API из шагов 1–4
- [ ] Телефоны, email, IBAN, карты заменяются плейсхолдерами `{{KIND_N}}`; одинаковые значения — одним плейсхолдером
- [ ] Цены, даты и короткие числа не маскируются (тесты на ложные срабатывания)
- [ ] Обратная подстановка восстанавливает значения; неизвестные плейсхолдеры не роняют функцию
- [ ] Модуль без побочных эффектов (нет обращений к БД/сети)
- [ ] Все тесты шага 5 написаны и проходят

## 🔍 Ревью

**Вердикт: CHANGES_REQUESTED**

1. `lib/ai/masking.ts` (`IBAN_PATTERN`, `extractIbanValue`) поглощает обычный
   текст после структурно корректного IBAN с неверной контрольной суммой. Пример:
   `maskText("Test-IBAN DE00 3704 0044 0532 0130 00 bitte verwenden.")`
   возвращает entity со значением
   `DE00 3704 0044 0532 0130 00 bitte verwend` и masked text
   `Test-IBAN {{IBAN_1}}en.`. По тикету checksum не обязательна, поэтому граница
   IBAN должна определяться без поглощения следующей фразы. Исправить определение
   границы и добавить регрессионный тест для IBAN без валидной checksum перед
   обычным словом.
2. `lib/ai/masking.ts` (`CARD_PATTERN` → `PHONE_PATTERN`) не изолирует
   card-shaped последовательность после непрохождения Луна. Пример:
   `maskText("Kartennummer: 0123 4567 8901 2345.")` возвращает
   `Kartennummer: {{PHONE_1}} 2345.` с entity `0123 4567 8901`: невалидная карта
   частично маскируется как телефон. Это нарушает требуемые проверку Луна и порядок
   обработки пересекающихся цифровых regex. Исключить частичную обработку
   card-shaped кандидата телефонным детектором и добавить регрессионный тест.
