# 11. Realtime, Web Push, PWA

> [!info] Навигация
> ⬅️ [10. UI и навигация](10-ui.md) · ⬆️ [Оглавление](_index.md) · ➡️ [12. Структура репозитория](12-repo-structure.md)

Экраны и навигация вынесены в отдельную главу — [10. UI и навигация](10-ui.md).

## Realtime

Подписка на `insert`/`update` в `messages` и `drafts` текущего workspace —
открытый инбокс живёт сам.

## Web Push

Через Serwist-воркер; отправка — Inngest-функция `send-push`
([7.6](07-data-flows.md#66-полный-список-inngest-функций)), библиотека web-push, VAPID
(ключи — [13. Секреты](13-environments-secrets.md#секреты-vercel-env)).
Подписки хранятся в [`push_subscriptions`](06-data-model.md#push_subscriptions).

### Частота уведомлений

Частота одна и не настраивается: **push на каждое входящее**. Текст —
«{имя} ({канал}) — Новое сообщение», клик открывает нужный диалог. Отправляет
`send-push`; событие эмитит вебхук-пайплайн сразу после записи сообщения. Про
черновик push не говорит — его ещё нет, генерацию запускает оператор.

Пользователь управляет только подпиской конкретного устройства — включает и
выключает её в разделе «Приложение» настроек
([10. Разделы настроек](10-ui.md#разделы-настроек)), рядом с установкой PWA.
Получатели push — все подписки workspace из
[`push_subscriptions`](06-data-model.md#push_subscriptions); отдельной таблицы
настроек у контура нет.

> [!note] Почему нет дайджеста
> Режим «сводка по интервалу» был в первой версии контура и убран: он усложнял
> контур (cron-функция, граница «что уже вошло в сводку», своя таблица
> настроек) ради выбора, который в инбоксе малого бизнеса не нужен — входящих
> немного, а задержка ответа стоит дороже лишнего уведомления.

> [!note] Почему в push нет контента переписки
> Push-payload проходит через инфраструктуру Apple/Google — держим там имена,
> названия каналов и счётчики, но не текст сообщений
> (минимизация данных — [15. Compliance](15-compliance-gdpr.md)).

> [!warning] iOS
> Push работает только для **установленной на экран** PWA (iOS ≥ 16.4) — отражаем в онбординге.
> См. [17. Риски](17-risks.md) и [Этап 9](16-rollout-plan.md#этап-9--pwa-и-push-1-2-дня).
