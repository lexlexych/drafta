# Создание публикаций: Drafta и Custom GPT

## Мастер Drafta (preview)

Основной сценарий — «Создать через draft». ChatGPT остаётся отдельным fallback.
Первый шаг: подключённые Instagram и LinkedIn, выбранные элементы базы знаний,
тип и язык. Доступны `text`, `image`, `carousel` и `video` (сценарий самостоятельной
съёмки). Текст без изображения публикуется только в LinkedIn. Выбор каналов при
создании задаёт версии текста; отправка требует отдельного предпросмотра и нажатия
«Опубликовать сейчас».

«Предложить идеи» ведёт на опциональный шаг 2: по три идеи, максимум 12 на черновик.
«Далее» пропускает идеи. Шаг 3 содержит редактируемые тему, цель, действие читателя,
аудиторию, тон и описание; для картинки — пропорции. Далее оформление картинки
(генерация или собственный файл, стиль, цвета, надпись, референс), проверка и генерация.
Текстовый сценарий пропускает оформление. Все вводные и идеи сохраняются сервером.

`publication_drafts.source` отделяет `draft` от `chatgpt`; OAuth видит только
свои `chatgpt`-черновики. `publication_authoring` хранит вводные, шаг, идеи,
ключ контекста идей, ревизию, активную задачу и версии текстов по `channelId`.
`publication_generation_jobs` — durable outbox, снимок вводных, промежуточный результат,
стадия, ошибка и usage OpenAI. Обе таблицы имеют workspace FK, RLS и каскады.
Записи задач не доступны браузеру через Data API; приложение возвращает только
состояние и результат последней задачи, без снимков и служебных полей.

`publication_authoring_action` блокирует черновик и состояние в одном порядке.
Автосохранение использует optimistic revision; во время задачи вводные заблокированы.
Лимиты: 12 идей на черновик, 100 новых задач на workspace за скользящие сутки,
не более трёх пользовательских попыток одной задачи. Дневной лимит сериализован
advisory lock по workspace. Повтор request ID идемпотентен.

OpenAI вызывается только из `lib/ai/publications.ts`: Responses со structured outputs
для идей и текста (`store: false`), Image API для картинки, edits для выбранного
референса. Текстовые идентификаторы маскируются, затем восстанавливаются в JSON-полях
ответа. Изображение-референс передаётся как выбранный пользователем файл и не может
быть обезличено текстовым маскированием. В надписи на AI-картинке личные идентификаторы
исключаются; точная типографика не гарантируется. Веб-поиск в эту версию не входит.

`publication-generation` выполняется через Inngest; события и результаты шагов —
только ID. Текст сохраняется до вызова image API, поэтому повтор ошибки изображения
не генерирует текст заново. Фонового восстановления по расписанию нет. Ошибка
отправки события сохраняется в задаче и сразу открывает кнопку повтора в UI;
pending-состояние сохраняется, поскольку событие могло дойти до потери подтверждения.
Если pending-задача не обновлялась 10 минут, UI показывает предупреждение и кнопку
«Повторить запуск»: по клику отправляется тот же ID без сброса готовых этапов.
SDK-ретраи отключены, временные ошибки повторяет Inngest;
исправимые ошибки модели/квоты переводятся в явную ошибку. После отзыва membership
новые этапы не выполняются.

Результат генерации — предложение. Только «Сохранить черновик» заменяет сохранённый
текст/картинку. Ручные правки и фоновые результаты не перезаписывают друг друга;
принятие устаревшей ревизии отклоняется. Тексты адаптируются отдельно по выбранным
каналам, картинка общая. Собственная картинка сохраняется в исходных пропорциях.

Завершённые задачи и их снимки/usage удаляются через 30 дней. Очистка файлов учитывает
вводные мастера и результаты/снимки ещё хранящихся задач. Вводные и принятые черновики
живут до удаления материала или workspace. API-ключ и настройки моделей — серверные переменные,
отдельные от Mistral/OpenRouter. Проверка и запуск: [native-publications.md](../integrations/native-publications.md).

## Карусели, сценарии и точечные правки

Карусель: 2–10 редактируемых описаний слайдов, AI-предложение структуры до генерации,
общие стиль и пропорции. Каждое изображение генерируется отдельным durable-шагом;
первый готовый слайд служит референсом серии. Готовые слайды можно переставлять,
заменять своими, добавлять и удалять (минимум два).

Сценарий: длительность 15–600 секунд, формат съёмки, сцены с хронометражем,
репликами и текстом на экране. Сохраняется как `kind=video`, но не содержит видеофайла
и не отправляется в соцсети. Доступны копирование и правка текста/отдельной сцены
по комментарию пользователя.

«Изменить с AI» раскрывает поле «Что изменить?». В снимок задачи входят сохранённая
версия и `revisionRequest`: инструкция и ID выбранного канала либо изображения.
Текстовая правка сохраняет остальные версии; Image API edits получает именно
текущее выбранное изображение. Остальные слайды сохраняются без изменения. Новое
предложение можно сохранить или отклонить; сохранённый материал до принятия не
меняется. Инструкции маскируются перед API вместе с остальным текстом.

## Отправка и удаление

`publication_deliveries` — отдельная задача на пару черновик/подключение. Таблица
имеет workspace FK, составные FK, RLS и каскады; снимки, временные ссылки и ошибки
транспорта не читаются браузером напрямую. `queue_publication` блокирует черновик,
проверяет ревизию, membership, активность каналов, тип, количество медиа и длину
текста (Instagram 2200, LinkedIn 3000). Повтор возвращает ту же задачу. Содержимое
отправленного материала фиксируется; статусы целей независимы.

`publication-send` отправляет через адаптер из `lib/channels/`, с ретраями Inngest.
События/результаты шагов содержат только ID. Фоновой проверки отправок нет.
В UI у каждой неудачной цели есть «Повторить», у ожидающей подтверждения —
«Проверить статус». Только нажатие отправляет событие с прежним ID задачи.
При ошибке доставки события сохраняется видимая ошибка; транспортные ID и состояние
не сбрасываются, поскольку событие могло быть принято до потери подтверждения. Изображения
локально преобразуются в JPEG с белыми полями вместо обрезки; для LinkedIn карусель
собирается в PDF. Производные файлы остаются в приватном Storage и учитываются
очисткой. Провайдер получает временные signed URL, браузер — авторизованный proxy.

Один `x-request-id` и неизменные медиа используются для повторов. После истечения
пятиминутного окна провайдера повторное создание запрещено: выполняется поиск по
техническому ID задачи в metadata. Известный remote ID проверяется GET; повтор
подтверждённой неудачи использует retry того же поста. Неопределённый результат
отображается явно и не приводит к слепой повторной отправке. Перед отправкой
повторно проверяются доступ автора и активность подключения.

Удаление доступно из списка и редактора с подтверждением. RPC блокирует удаление
во время генерации, импорта или незавершённой отправки. Удаление материала в Drafta
не удаляет пост в соцсети; его комментарии остаются в `posts`/`comments`.
Планировщик, загрузка/генерация видео и правки уже опубликованных постов не входят
в этот этап.

## Границы

Один публичный Custom GPT обслуживает клиентов. Он читает выбранные знания и
отправляет черновики; публикации в соцсети нет. Генерация выполняется в ChatGPT
пользователя, поэтому Drafta не вызывает LLM в этом контуре и не использует
системные промпты переписки/комментариев как бриф публикации.

`publication_draft` — черновик будущей публикации. Это отдельная сущность от
`posts` (уже опубликованные посты с комментариями), `drafts` (ответы в переписке)
и `comment_drafts` (ответы на комментарии).

## Авторизация

Drafta выступает OAuth authorization server для одного confidential client —
общего GPT. Authorization endpoint `/oauth/authorize` использует вход Supabase
и форму согласия (Next Server Action с проверкой origin), выбор workspace и
категорий. Проверяются точное совпадение redirect URI из серверного allowlist,
client ID, response type, state и scopes. При передаче PKCE разрешён только S256.

`/api/gpt/oauth/token` принимает authorization_code и refresh_token, с client
secret в POST или HTTP Basic. Код действует пять минут; access token — час;
grant и refresh — до 30 дней от подключения. Коды и токены случайные, по 32 байта,
в БД только SHA-256. Обмен и ротация — условное атомарное обновление: повторное
использование уже потреблённого credential не выдаёт токен. Membership проверяется
при каждом API-запросе и обновлении токена. Секреты не доступны через Data API.
Отключение в панели отзывает все grants пользователя для текущего workspace.

На grant действует предел 60 API-вызовов в минуту. Тексты, токены и временные
ссылки не попадают в application logs. Ответы API — `no-store`.

## Данные и разрешения

Все четыре таблицы имеют `workspace_id`, RLS и каскад от workspace:

- `publication_drafts`: автор, текст, тип, контекст генерации, упорядоченные asset IDs,
  статус, время первого ручного редактирования, активный импорт;
- `publication_assets`: принадлежность черновику и путь в приватном Storage;
- `gpt_oauth_grants`: пользователь, разрешённые категории, хеши credentials,
  callback, сроки и счётчик запросов;
- `publication_imports`: request ID, digest содержимого, временный payload и статус.

Черновики и медиа читают все участники workspace. Изменения идут через сервер,
который проверяет membership и workspace. GPT получает только созданные подключённым
пользователем черновики. Межтенантные ссылки на медиа исключены составными FK и
проверкой принадлежности в RPC. Storage отдаётся браузеру через авторизованный
`/api/publications/assets/[id]`; только явно выбранный логотип может быть передан
ChatGPT как короткоживущая signed URL.

База знаний — пересечение активных категорий workspace, выбранных в контексте
черновика и разрешённых конкретным OAuth grant. Неотмеченные аудитория, тон, цвета
и логотип не передаются. Язык, количество слайдов, формат и текст на изображениях
выбираются в Drafta и уточняются в GPT. Регион и конкуренты берутся из знаний;
при отсутствии GPT задаёт вопросы. Ответ знаний ограничен бюджетом Actions;
при превышении предлагается сократить набор категорий, без скрытого усечения.

## Импорт и редактирование

Два бизнес-endpoint: GET `/api/gpt/knowledge` и POST
`/api/gpt/publication-drafts`. Первый без draft_id перечисляет назначения;
с draft_id возвращает контекст и новый request_id. Второй принимает текст,
1 картинку либо 2–10 изображений и явный `file_order`.

Резервирование импорта блокирует строку черновика. Дубликат request_id с тем же
содержимым возвращает прежний импорт; изменённое содержимое конфликтует. После
начала ручного редактирования новый импорт запрещён. Пока импорт идёт, редактор
не может получить блокировку для ручных изменений. Завершение проверяет активный
импорт и вручную отредактированное состояние повторно под блокировкой строки.

Маршрут сохраняет payload и отправляет Inngest только workspaceId/importId.
`publication-import` скачивает изображения пачками по три, проверяя точный
allowlist OpenAI, HTTPS, отсутствие credentials/нестандартного порта, запрет
redirect, байтовый предел и сигнатуру PNG/JPEG/WebP. Данные не возвращаются из
шагов Inngest, только IDs. Изображения копируются в Supabase Storage; текст и
порядок заменяются после успешного импорта всего набора. При ошибке прежнее
содержимое сохраняется. Временный payload удаляется после успеха/ошибки.

Фонового запуска импорта нет. Сбой отправки события завершает импорт ошибкой,
которую показывает UI. «Повторить импорт» вручную отправляет тот же ID, пока ссылки
действительны. После 4,5 минуты UI показывает истечение времени; нажатие завершает
зависшую задачу ошибкой и предлагает свежую передачу через «Повторить через ChatGPT».
Ошибочный импорт с уже удалённым payload также требует свежих файлов. Realtime и
резервный опрос обновляют панель; пользовательские несохранённые изменения
не заменяются фоновым обновлением. Ручная работа включает текст, загрузку,
замену, удаление и перестановку изображений. Изменённый черновик больше не
принимает новые версии GPT.

## Ретенция и проверка

`cleanup-publication-assets` ежечасно удаляет до 100 неиспользуемых файлов старше
суток, в том числе оставшихся после каскада удаления workspace, а также метаданные.
Эта же очистка удаляет завершённые задачи генерации старше 30 дней.
Просроченные grants удаляются; завершённые imports хранятся 30 дней для
идемпотентности. Активные черновики сохраняются до удаления workspace.

Unit/UI-тесты — `lib/publications/*.test.ts` и тест панели. Проверки SQL/RLS и
блокировки — `supabase/tests/publication_drafts.test.sql`, запуск `supabase test db`
после локальных миграций и seed. Перед публичным запуском обязательна ручная
проверка настоящих изображений текущего генератора в созданном пользователем GPT.
