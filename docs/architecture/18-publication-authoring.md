# Создание публикаций через Custom GPT

Связанный документ: [ручная настройка общего GPT](../integrations/custom-gpt-publications.md).

## Границы

Один публичный Custom GPT обслуживает клиентов. Он читает выбранные знания и
отправляет черновики; публикации в соцсети нет. Генерация выполняется в ChatGPT
пользователя, поэтому Drafta не вызывает LLM в этом контуре и не использует
системные промпты переписки/комментариев как бриф публикации.

`publication_draft` — черновик будущей публикации. Это отдельная сущность от
`posts` (уже опубликованные посты с комментариями), `drafts` (ответы в переписке)
и `comment_drafts` (ответы на комментарии).

## Авторизация

Drafta выступает OAuth authorization server для одного confidential client —
общего GPT. Authorization endpoint `/oauth/authorize` использует вход Supabase
и форму согласия (Next Server Action с проверкой origin), выбор workspace и
категорий. Проверяются точное совпадение redirect URI из серверного allowlist,
client ID, response type, state и scopes. При передаче PKCE разрешён только S256.

`/api/gpt/oauth/token` принимает authorization_code и refresh_token, с client
secret в POST или HTTP Basic. Код действует пять минут; access token — час;
grant и refresh — до 30 дней от подключения. Коды и токены случайные, по 32 байта,
в БД только SHA-256. Обмен и ротация — условное атомарное обновление: повторное
использование уже потреблённого credential не выдаёт токен. Membership проверяется
при каждом API-запросе и обновлении токена. Секреты не доступны через Data API.
Отключение в панели отзывает все grants пользователя для текущего workspace.

На grant действует предел 60 API-вызовов в минуту. Тексты, токены и временные
ссылки не попадают в application logs. Ответы API — `no-store`.

## Данные и разрешения

Все четыре таблицы имеют `workspace_id`, RLS и каскад от workspace:

- `publication_drafts`: автор, текст, тип, контекст генерации, упорядоченные asset IDs,
  статус, время первого ручного редактирования, активный импорт;
- `publication_assets`: принадлежность черновику и путь в приватном Storage;
- `gpt_oauth_grants`: пользователь, разрешённые категории, хеши credentials,
  callback, сроки и счётчик запросов;
- `publication_imports`: request ID, digest содержимого, временный payload и статус.

Черновики и медиа читают все участники workspace. Изменения идут через сервер,
который проверяет membership и workspace. GPT получает только созданные подключённым
пользователем черновики. Межтенантные ссылки на медиа исключены составными FK и
проверкой принадлежности в RPC. Storage отдаётся браузеру через авторизованный
`/api/publications/assets/[id]`; только явно выбранный логотип может быть передан
ChatGPT как короткоживущая signed URL.

База знаний — пересечение активных категорий workspace, выбранных в контексте
черновика и разрешённых конкретным OAuth grant. Неотмеченные аудитория, тон, цвета
и логотип не передаются. Язык, количество слайдов, формат и текст на изображениях
выбираются в Drafta и уточняются в GPT. Регион и конкуренты берутся из знаний;
при отсутствии GPT задаёт вопросы. Ответ знаний ограничен бюджетом Actions;
при превышении предлагается сократить набор категорий, без скрытого усечения.

## Импорт и редактирование

Два бизнес-endpoint: GET `/api/gpt/knowledge` и POST
`/api/gpt/publication-drafts`. Первый без draft_id перечисляет назначения;
с draft_id возвращает контекст и новый request_id. Второй принимает текст,
1 картинку либо 2–10 изображений и явный `file_order`.

Резервирование импорта блокирует строку черновика. Дубликат request_id с тем же
содержимым возвращает прежний импорт; изменённое содержимое конфликтует. После
начала ручного редактирования новый импорт запрещён. Пока импорт идёт, редактор
не может получить блокировку для ручных изменений. Завершение проверяет активный
импорт и вручную отредактированное состояние повторно под блокировкой строки.

Маршрут сохраняет payload и отправляет Inngest только workspaceId/importId.
`publication-import` скачивает изображения пачками по три, проверяя точный
allowlist OpenAI, HTTPS, отсутствие credentials/нестандартного порта, запрет
redirect, байтовый предел и сигнатуру PNG/JPEG/WebP. Данные не возвращаются из
шагов Inngest, только IDs. Изображения копируются в Supabase Storage; текст и
порядок заменяются после успешного импорта всего набора. При ошибке прежнее
содержимое сохраняется. Временный payload удаляется после успеха/ошибки.

Recovery cron раз в минуту повторяет событие для зависших pending-записей; старые
ссылки завершаются ошибкой и требуют новой передачи из ChatGPT. Realtime и
резервный опрос обновляют панель; пользовательские несохранённые изменения
не заменяются фоновым обновлением. Ручная работа включает текст, загрузку,
замену, удаление и перестановку изображений. Изменённый черновик больше не
принимает новые версии GPT.

## Ретенция и проверка

`cleanup-publication-assets` ежечасно удаляет до 100 неиспользуемых файлов старше
суток, в том числе оставшихся после каскада удаления workspace, а также метаданные.
Просроченные grants удаляются; завершённые imports хранятся 30 дней для
идемпотентности. Активные черновики сохраняются до удаления workspace.

Unit/UI-тесты — `lib/publications/*.test.ts` и тест панели. Проверки SQL/RLS и
блокировки — `supabase/tests/publication_drafts.test.sql`, запуск `supabase test db`
после локальных миграций и seed. Перед публичным запуском обязательна ручная
проверка настоящих изображений текущего генератора в созданном пользователем GPT.
