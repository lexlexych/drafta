# 14. Правила вайбкодинга (содержимое CLAUDE.md)

> [!info] Навигация
> ⬅️ [13. Окружения, секреты, деплой](13-environments-secrets.md) · ⬆️ [Оглавление](_index.md) · ➡️ [15. Compliance](15-compliance-gdpr.md)

При разработке через AI-агента архитектура держится не на памяти разработчика,
а на **явных правилах в репозитории** (см. [1. Условия разработки](01-overview.md#масштаб-и-условия-разработки)).

## Минимальный набор правил

| # | Правило | Откуда |
|---|---|---|
| 1 | Глоссарий: тенант всегда `workspace`, никогда `account` | [§2](02-glossary.md) |
| 2 | Схема БД меняется **только** миграциями в `supabase/migrations`, никаких правок через дашборд | [§12](12-repo-structure.md) |
| 3 | Каждая новая таблица — сразу с `workspace_id`, RLS-политиками и каскадным удалением от workspace | [§6](06-data-model.md) |
| 4 | Провайдер-специфичный код — только в `lib/channels/`, ядро импортирует только нормализованные типы | [§5](05-channels.md#дисциплина) |
| 5 | `SUPABASE_SECRET_KEY` — только в серверном коде | [§13](13-environments-secrets.md#секреты-vercel-env) |
| 6 | Вебхук-роуты не вызывают LLM и отвечают < 1 сек; вся тяжёлая работа — события Inngest | [§7.1](07-data-flows.md#61-входящее-dm-или-комментарий) |
| 7 | **Payload событий Inngest — только ID, никогда персональные данные** | [§7.2](07-data-flows.md#62-дебаунс-и-генерация-черновика) |
| 8 | Любая внешняя отправка — через Inngest-функцию с ретраями, не из запроса | [§7.3](07-data-flows.md#63-отправка-ответа) |
| 9 | Вызовы LLM — генерация и классификация по категориям — только через `lib/ai` (с маскированием), напрямую SDK не дёргать | [§8](08-ai-subsystem.md#маскирование-идентификаторов-перед-llm) |
| 10 | Auth-письма шлёт Supabase (через Postmark-SMTP) — свой код отправки инвайтов не писать | [§4](04-multitenancy.md#приглашения) |
| 11 | Новые внешние сервисы не добавлять без обновления списка субпроцессоров | [§15](15-compliance-gdpr.md#122-субпроцессоры-и-данные) |
| 12 | После каждой фичи — прогон smoke-тестов | ниже |

## Тесты

Тесты — то, что защищает вайбкодинг от регрессий, когда код никто не читает построчно:

- **Юнит-тесты на адаптеры** — фикстуры реальных payload'ов Zernio/Postmark → ожидаемые
  нормализованные события. Это одновременно «контракт» абстракции
  ([§5](05-channels.md#нормализованное-событие)).
- **Тесты RLS-политик** — member не видит чужой workspace ([§4](04-multitenancy.md#изоляция-данных)).
- **Юнит-тесты маскирования** ([§8](08-ai-subsystem.md#маскирование-идентификаторов-перед-llm)).
- **Один Playwright-сценарий** — «вебхук → сообщение в инбоксе → черновик → отправка» на стейджинге.

> [!tip] Фикстуры бесплатны
> Сырые payload'ы накапливаются сами — они уже лежат в
> [`webhook_events`](06-data-model.md#webhook_events).

> [!important] «Несущие стены»
> Глоссарий + `CLAUDE.md` + тесты-контракты на адаптеры, RLS и маскирование — это то,
> что агент не может незаметно сломать. Обоснование — [17. Риски](17-risks.md).
