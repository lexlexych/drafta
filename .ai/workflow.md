# Агентский workflow: эпики и тикеты

Единый источник правды о процессе разработки через AI-агентов.
Работает одинаково в Claude Code, Codex CLI и любой другой агентной среде.

## Роли

| Роль | Файл роли | Зона ответственности |
|---|---|---|
| Аналитик (`epic-analyst`) | `.ai/roles/analyst.md` | Превращает описание или этап из `docs/architecture/16-rollout-plan.md` в эпик с тикетами |
| Разработчик (`ticket-developer`) | `.ai/roles/developer.md` | Выполняет ровно один тикет |
| Ревьюер (`ticket-reviewer`) | `.ai/roles/reviewer.md` | Независимо проверяет выполненный тикет |
| Оркестратор | — (основная сессия) | Ведёт `/startEpic`: запускает роли, обновляет статусы. Сам код не пишет |

## Команды

| Команда | Процедура |
|---|---|
| `/createEpic <описание \| этап N>` | `.ai/commands/createEpic.md` |
| `/startEpic E-NNN` | `.ai/commands/startEpic.md` |

## Структура файлов

```
docs/epics/
├── STATUS.md                     # статус-борд всего проекта
└── epic_01/                      # эпик E-001
    ├── _index.md                 # описание эпика + таблица тикетов
    ├── T-01-<slug>.md            # тикеты (slug — латиницей, kebab-case)
    ├── T-02-<slug>.md
    └── T-NN-executive-summary.md # ВСЕГДА последний, type: manual — ручные шаги для человека
```

## Идентификаторы

- Эпик: `E-001` ↔ папка `epic_01` (номер сквозной, следующий свободный).
- Тикет: `T-01`, `T-02`, … внутри эпика; полная ссылка — `E-001/T-01`.
- Порядок выполнения тикетов = порядок номеров.

## Статусы

Тикет: `todo → in_progress → review → done`; из `review` возможно `rework → in_progress`;
из любого — `blocked`. Тикет `type: manual` агентами не выполняется (его закрывает человек).

Эпик: `todo → in_progress → manual_steps → done`; из любого — `blocked`.
`manual_steps` — все dev-тикеты готовы, остались ручные шаги из executive summary.

## Правила процесса

1. Тикеты выполняются **строго последовательно**, один за раз. Никакой параллельности.
2. Один тикет = один изолированный запуск разработчика + один изолированный запуск ревьюера.
3. Вся проделанная работа документируется **в файле тикета** (разделы «Отчёт разработчика» и «Ревью»).
4. Статусы меняет **только оркестратор** (и аналитик при создании) — в трёх местах сразу:
   frontmatter тикета, таблица в `_index.md` эпика, `docs/epics/STATUS.md`.
   Источник правды — frontmatter тикета; остальные два — синхронизируемые представления.
5. Максимум **2 цикла доработки** по замечаниям ревью. Не помогло — тикет `blocked`,
   эпик останавливается, оркестратор пишет отчёт человеку.
6. Ручные действия (настройки в дашбордах, секреты, DNS и т.п.) агенты **не выполняют** —
   они дописываются шагами в executive-summary-тикет эпика.
7. Весь код подчиняется `docs/architecture/14-vibecoding-rules.md` и глоссарию
   `docs/architecture/02-glossary.md`.

## Универсальность сред

- **Среда с суб-агентами** (Claude Code): каждую роль запускает изолированный суб-агент
  (`.claude/agents/epic-analyst`, `ticket-developer`, `ticket-reviewer`). Оркестратор ждёт
  завершения каждого суб-агента, прежде чем запускать следующего.
- **Среда без суб-агентов** (Codex CLI): одна сессия исполняет роли последовательно.
  Перед каждой ролью — прочитать её файл из `.ai/roles/` и играть только её. Правило
  изоляции: роль опирается **только на файлы** (тикет, документация, код), а не на память
  сессии о предыдущих ролях; ревьюер обязан перепроверять всё сам, а не «вспоминать»,
  что код писался только что.

Артефакты (тикеты, отчёты, статусы) в обеих средах идентичны — результат работы
не зависит от того, где она велась.
