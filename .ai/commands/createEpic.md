# Команда /createEpic — создать эпик

Процедура для основной сессии (оркестратора). Аргументы — текст после имени команды.

## Шаги

1. **Разбери аргументы.**
   - Пусто → спроси пользователя, что должно войти в эпик, и остановись до ответа.
   - Совпадает с шаблоном «этап N» / «stage N» / ссылкой на раздел плана внедрения →
     источник эпика: соответствующий этап из `docs/architecture/16-rollout-plan.md`.
   - Иначе → источник — свободное текстовое описание (аналитик всё равно обязан
     сверить его с документацией и найти релевантные главы).
2. **Определи номер эпика**: просмотри `docs/epics/` (папки `epic_NN`) и возьми
   следующий свободный номер. ID эпика — `E-0NN`, папка — `epic_NN`.
3. **Запусти аналитика** с заданием: номер эпика, папка, источник (текст или номер этапа).
   - Среда с суб-агентами (Claude Code): запусти суб-агента `epic-analyst` синхронно
     и дождись завершения.
   - Среда без суб-агентов (Codex CLI): прочитай `.ai/roles/analyst.md` и выполни
     роль сам, строго по ней.
   Аналитик работает по `.ai/roles/analyst.md`: изучает документацию, декомпозирует,
   создаёт `_index.md` и тикеты по шаблонам `.ai/templates/`, последним — обязательный
   executive-summary-тикет (`type: manual`), регистрирует эпик в `docs/epics/STATUS.md`.
4. **Проверь результат**: папка создана, есть `_index.md`, тикеты пронумерованы без
   пропусков, последний — executive summary, эпик появился в `STATUS.md`.
5. **Отчитайся пользователю**: ID и цель эпика, таблица тикетов (номер — название —
   одна строка сути), открытые вопросы аналитика, и подсказка: запуск —
   `/startEpic E-0NN`.
