# Команда /startEpic — выполнить эпик

Процедура для основной сессии (оркестратора). Аргумент — ID эпика.
Оркестратор координирует и ведёт статусы; код он **не пишет** — это делают роли.

## Подготовка

1. **Нормализуй аргумент**: `E-001`, `e-001`, `E001`, `1`, `epic_01` → папка
   `docs/epics/epic_01/`, ID `E-001`. Папки нет → покажи список эпиков из
   `docs/epics/STATUS.md` и остановись.
2. **Прочитай** `_index.md` эпика, `docs/epics/STATUS.md` и frontmatter всех тикетов.
3. **Оцени состояние эпика**:
   - `done` → сообщи, что эпик завершён, и остановись.
   - `manual_steps` → все dev-тикеты готовы; покажи пользователю ручные шаги из
     executive-summary-тикета и напомни: после их выполнения эпик закрывается
     командой `/finishEpic E-0NN` (статусы + merge в `main`). Остановись.
   - `blocked` → покажи причину (тикет со статусом `blocked` и его ревью) и спроси,
     как поступить. Остановись.
   - иначе → продолжай; если эпик `todo` — переведи в `in_progress`.
4. **Git и ветка эпика** (политика — `.ai/workflow.md`, раздел «Git-политика»):
   - git не инициализирован → `git init -b main` и первый коммит всего текущего
     содержимого (`chore: initial commit`);
   - есть незакоммиченные изменения → остановись и спроси пользователя, что с ними
     делать (в stash молча не прятать);
   - ветка `E-0NN` существует → переключись на неё; нет → создай от `main`
     (`git checkout -b E-0NN main`);
   - вся дальнейшая работа эпика (код, отчёты, статусы) идёт в этой ветке;
     в `main` напрямую не коммитить, ветки до конца эпика не переключать.
5. **Построй очередь**: dev-тикеты (`type: dev`) в порядке номеров со статусом не `done`.
   Это даёт возобновление после прерывания: уже готовые тикеты пропускаются.
   Тикет, застрявший в `in_progress`/`review`/`rework`, выполняется заново
   (разработчику в промпте указывается, что предыдущий запуск был прерван —
   начать с проверки фактического состояния кода).

## Цикл по тикетам (строго последовательно)

Для каждого тикета из очереди:

1. Статус тикета → `in_progress` (frontmatter + `_index.md` + `STATUS.md`).
2. **Разработчик.** Запусти роль с промптом:
   «Выполни тикет `<путь к тикету>`. Эпик: `<путь к _index.md>`.
   Работай строго по `.ai/roles/developer.md`.»
   - Claude Code: суб-агент `ticket-developer`, синхронно (дождись завершения,
     `run_in_background: false`).
   - Без суб-агентов: прочитай `.ai/roles/developer.md` и выполни роль сам.
3. Статус тикета → `review`.
4. **Ревьюер.** Запусти роль с промптом:
   «Проверь тикет `<путь к тикету>`. Эпик: `<путь к _index.md>`.
   Работай строго по `.ai/roles/reviewer.md`.»
   - Claude Code: суб-агент `ticket-reviewer`, синхронно.
   - Без суб-агентов: выполни роль сам, по файлам, ничему не доверяя «по памяти».
5. **По вердикту из раздела «Ревью» тикета**:
   - `APPROVED` → статус тикета `done` (все три места), служебный коммит в ветку
     эпика (`[E-0NN/T-NN] review: approved, status: done` — тикет-файл, `_index.md`,
     `STATUS.md`), краткая строка прогресса пользователю («T-03 done, 3/7»),
     переходи к следующему тикету.
   - `CHANGES_REQUESTED` → статус `rework` + служебный коммит
     (`[E-0NN/T-NN] review: changes requested`), запусти разработчика заново с промптом
     «Устрани замечания из раздела „Ревью“ тикета `<путь>`…», затем снова ревьюера
     (шаги 2–4). Максимум **2 цикла доработки**; не помогло → статус тикета `blocked`,
     эпик `blocked`, остановись и доложи пользователю: что застряло, замечания ревью,
     варианты действий.

## Завершение

1. Все dev-тикеты `done` → эпик `manual_steps` (frontmatter `_index.md` + `STATUS.md`)
   + коммит `[E-0NN] epic: manual_steps`.
2. **Финальный отчёт пользователю**:
   - что реализовано по тикетам (по строке на тикет);
   - отклонения, «вне скоупа» и открытые вопросы из отчётов;
   - ветка эпика `E-0NN` и число коммитов в ней (в `main` пока ничего не влито);
   - главное: ссылка на `T-NN-executive-summary.md` и его шаги — что нужно сделать
     руками, чтобы эпик заработал; после проверки и выполнения шагов —
     `/finishEpic E-0NN` (закроет эпик и вольёт ветку в `main`).

## Правила оркестратора

- Никогда не запускай двух агентов параллельно — только последовательно.
- Статусы обновляй сразу при каждом переходе, не пакетом в конце: при прерывании
  сессии `STATUS.md` должен отражать реальное состояние.
- Не редактируй код и отчёты ролей; твои файлы — frontmatter статусов, `_index.md`,
  `STATUS.md`.
- Служебные изменения коммить в ветку эпика сразу после каждого ревью/перехода
  статуса; в `main` не коммитить и не мерджить — merge делает только `/finishEpic`.
